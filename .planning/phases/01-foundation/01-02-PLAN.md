    1. `backend/src/middleware/authMiddleware.js`:
       ```js
       const { verifyAccessToken } = require('../utils/jwt');
       const userModel = require('../models/userModel');
       module.exports = async function authMiddleware(req, res, next) {
         const header = req.headers.authorization || '';
         const token = header.startsWith('Bearer ') ? header.slice(7) : null;
         if (!token) return res.status(401).json({ error: 'missing_token' });
         try {
           const decoded = verifyAccessToken(token);
           const user = await userModel.findById(decoded.sub);
           if (!user || !user.is_active) return res.status(401).json({ error: 'invalid_token' });
           req.user = user;
           next();
         } catch {
           return res.status(401).json({ error: 'invalid_token' });
         }
       };
       ```

    2. `backend/src/middleware/roleMiddleware.js` (per D-16, BE-05):
       ```js
       exports.requireRole = (...roles) => (req, res, next) => {
         if (!req.user) return res.status(401).json({ error: 'unauthenticated' });
         if (!roles.includes(req.user.role)) return res.status(403).json({ error: 'forbidden' });
         next();
       };
       exports.requirePermission = (perm) => (req, res, next) => {
         if (!req.user) return res.status(401).json({ error: 'unauthenticated' });
         const perms = Array.isArray(req.user.permissions) ? req.user.permissions : JSON.parse(req.user.permissions || '[]');
         if (!perms.includes(perm) && req.user.role !== 'admin') return res.status(403).json({ error: 'forbidden' });
         next();
       };
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/login | Untrusted credentials — primary brute-force target |
| client → /api/auth/refresh | Refresh cookie is long-lived (7d); theft enables session takeover |
| backend → MySQL | Password hashes at rest; compromised DB must not leak plaintext |
| backend → process.env | JWT secrets live in env vars — must not log or expose |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Information Disclosure | users.password_hash | mitigate | bcrypt with rounds=10 per D-14; `password.js` is the ONLY place that calls bcrypt; userModel.findById excludes `password_hash` from SELECT |
| T-01-07 | Spoofing | /api/auth/login | mitigate | express-rate-limit 10 req / 15 min per IP (loginLimiter); brute force becomes infeasible |
| T-01-08 | Tampering | JWT access token | mitigate | Signed with JWT_ACCESS_SECRET (env only, never logged); 15-min TTL limits replay window |
| T-01-09 | Information Disclosure | Refresh token | mitigate | httpOnly cookie (not reachable from JS → XSS-resistant); sameSite=strict (CSRF-resistant); path=/api/auth (scoped); secure=true in production |
| T-01-10 | Elevation of Privilege | Admin-only endpoints | mitigate | roleMiddleware.requireRole('admin') per BE-05; tested to return 403 for staff tokens |
| T-01-11 | Repudiation | Failed login attempts | accept | v1 logs to stdout via console.error; structured audit log deferred to v2 |
| T-01-12 | Information Disclosure | Error responses | mitigate | authController returns generic `invalid_credentials` (not "user not found" vs "wrong password") to avoid user enumeration |
| T-01-13 | Tampering | JWT secret rotation | accept | v1 uses single secret from env; rotation strategy (kid header, multiple secrets) deferred to v2 — documented in .env.example |
| T-01-14 | Denial of Service | MySQL connection exhaustion | mitigate | mysql2 pool with connectionLimit=10, waitForConnections=true |
| T-01-15 | Information Disclosure | CORS origin | mitigate | `cors({ origin: env.CORS_ORIGIN, credentials: true })` — explicit single origin, no wildcard with credentials (would be rejected by browser anyway) |
</threat_model>
