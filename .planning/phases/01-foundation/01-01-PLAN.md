<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → backend | Any HTTP request from Expo app (web/mobile) to Express — all input untrusted |
| dev → repo | Secrets committed to `.env` would leak; `.env.example` is the only committed secrets file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | backend/.env | mitigate | `.gitignore` includes `.env`; only `.env.example` is committed with placeholder secrets |
| T-01-02 | Tampering | Express request body | mitigate | `express.json({ limit: '1mb' })` caps payload size; input validation added per-route in Plan 02 |
| T-01-03 | Denial of Service | Express app | mitigate | `helmet()` sets secure headers; rate limiting applied to `/api/auth/*` in Plan 02 |
| T-01-04 | Information Disclosure | CORS | mitigate | `cors({ origin: env.CORS_ORIGIN, credentials: true })` — single origin, no wildcard with credentials |
| T-01-05 | Spoofing | Frontend imports | accept | Shared types import via relative path; bundler resolves at build — no runtime trust required |
</threat_model>
